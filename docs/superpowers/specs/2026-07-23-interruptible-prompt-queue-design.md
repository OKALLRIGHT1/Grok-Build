# 可控制的执行中指令队列设计

## 目标

用户在当前任务执行期间仍可提交下一步指令。提交后的指令必须保持可见，并可在电脑端或手机端编辑、删除和调整顺序；用户也可以明确选择“打断并发送”，在当前任务确认停止后立即执行指定指令。

## 根因

现有界面在主进程确认接收前清空输入框，主进程只公开队列长度，没有为队列项分配 ID 或公开内容。当前取消操作只通知 CLI 取消正在执行的请求，随后队列仍会自动继续，因此界面无法表达编辑、删除、插队或取消全部待执行项。

## 队列模型

每个待执行项包含稳定的 `id`、文本、附件、来源、创建时间和当前位置。队列只保存在电脑端主进程内存中，电脑和手机界面均从同一运行时快照读取，避免双端各自维护副本。

主进程提供列出、更新、删除、移动和立即执行队列项的操作。所有操作按队列项 ID 定位；运行时快照包含经过展示裁剪的文本和附件元数据，不包含附件二进制内容。

## 提交语义

空闲时普通发送立即执行。忙碌时普通发送加入队尾，并在后端返回队列项 ID 后清空输入。发送失败时保留原输入和附件。

“打断并发送”创建一个高优先级队列项，通知当前 CLI 请求取消，并等待当前 `session/prompt` 请求真正结束；结束后该项从队首执行。该过程不依赖固定延时，避免旧请求与新请求同时占用同一会话。

取消当前任务不会自动删除普通待执行项。界面提供单独的“清空待执行”操作。停止整个后端时清空队列，并通过运行时更新同步到所有客户端。

## 界面

编辑器上方显示紧凑的“待执行”区域，仅在队列非空时出现。每条指令显示顺序、单行摘要、附件数量，以及编辑、删除、上移、下移和打断当前任务立即执行操作。编辑时内容和附件回填到编辑器，保存后更新原队列项而不是新增一条。

电脑端发送按钮保持普通排队语义，并在旁边提供带停止图标的“打断并发送”按钮，仅在任务执行中显示。手机端使用同样语义和操作，不依赖长按或隐藏手势。

## 同步与错误处理

队列每次增删改、重排、开始执行或被清空后都广播完整运行时快照。编辑不存在或已经开始执行的 ID 时返回“该指令已开始执行或已被删除”，界面刷新队列且不覆盖编辑器内容。

客户端请求使用唯一请求 ID，重复到达的同一操作不得创建两条队列项。现有配对认证和附件大小限制保持不变。

## 测试

自动化测试覆盖：忙碌时入队、队列项稳定 ID、更新、删除、移动、打断项置顶、等待当前请求结束后执行、失败时输入保留，以及重复请求不重复入队。

Electron 和手机界面验证覆盖：队列展示、编辑回填、删除、重排、打断发送、双端实时同步、窄屏布局和当前任务结束时自动执行下一项。
