# iPad 响应式布局设计

## 目标

在不修改 CLI 后端、ACP 通信协议和手机端主要操作习惯的前提下，为 Grok Remote 增加适合 iPad 的响应式布局：横屏使用可折叠三栏，竖屏使用左右覆盖抽屉。

## 范围

本次仅修改电脑端提供的移动网页及其自动化验证。iPad 继续通过 Safari 或主屏幕 Web App 访问电脑端控制服务，不增加独立 iOS 安装包，也不修改 Android 包或 Rust 后端。

## 已选方案

采用统一响应式面板，而不是复用现有 `dialog` 强行排版，也不复制一套 iPad 专用业务界面。

移动网页包含三个稳定区域：

1. 左侧导航面板：当前工作区、新建对话和历史会话。
2. 中间对话区域：消息时间线、待执行队列和输入框。
3. 右侧控制面板：模型、运行模式、额度和当前任务。

同一套左右面板 DOM 根据视口变成横屏侧栏或竖屏抽屉，所有数据继续使用现有 WebSocket action 和渲染函数。

## 响应式规则

### 手机

手机维持当前单栏对话体验。会话和控制面板以覆盖层呈现，不因为横向手机宽度超过普通断点而进入三栏模式。

### iPad 竖屏

- 竖屏增强样式从 `700px` 宽度开始启用；更窄的分屏窗口按手机布局处理。
- 中间对话区域占满可用宽度。
- 左侧导航从左边缘覆盖式滑入。
- 右侧控制从右边缘覆盖式滑入。
- 打开任意抽屉时显示遮罩。
- 点击遮罩、按 `Esc` 或选择会话后关闭当前抽屉。
- 旋转到竖屏时两个抽屉默认关闭，不挤压对话内容。

### iPad 横屏

- 三栏模式仅在视口宽度至少 `980px`、高度至少 `650px` 且为横屏时启用，横屏手机继续使用单栏覆盖面板。
- 页面采用左侧导航、中间对话、右侧控制三栏网格。
- 左右栏均有独立的展开和收起按钮。
- 首次使用默认左栏展开、右栏收起。
- 用户调整后的横屏状态写入 `localStorage`，下次打开恢复。
- 从竖屏转回横屏时恢复最近一次保存的横屏状态。
- 三栏模式除宽度条件外还要求足够的可用高度，避免横屏手机误用 iPad 布局。
- `980px` 至 `1179px` 宽度使用约 `220px` 左栏和 `240px` 右栏；`1180px` 以上可分别扩展到约 `260px` 和 `300px`。
- 中间对话列最小宽度为 `480px`，侧栏不能把代码、工具输出和输入框压缩到不可用。

## 左侧导航

- 顶部显示当前工作区名称和连接状态。
- 提供新建对话命令。
- 打开时调用现有 `list-sessions` action。
- 历史会话按 `cwd` 工作区路径分组；缺少路径的记录归入“其他会话”。
- 当前会话高亮并标注模型与更新时间。
- 选择会话继续调用现有 `load-session` action，不引入新协议。
- 竖屏选择后关闭左抽屉；横屏保持左栏当前状态。

## 右侧控制

- 复用现有模型和运行模式选择器。
- 保留额度和任务能力；历史会话从右侧控制移到左侧导航，不渲染第二份会话列表。
- 额度和任务按当前刷新逻辑加载，不在布局切换时重复发起请求。
- 模型、模式或任务操作失败时，在右侧面板内显示错误并保留当前面板。

## 状态管理

新增一个小型、可独立测试的移动布局模块，负责：

- 根据视口宽度、高度和方向确定手机、iPad 竖屏或 iPad 横屏模式。
- 提供首次横屏状态 `{ leftOpen: true, rightOpen: false }`。
- 校验并读取本地保存的左右栏布尔状态。
- 保存用户在横屏中的调整。
- 对历史会话按工作区路径分组，供左侧导航渲染。

布局变化不得重建 WebSocket、重新配对、清空消息、清空附件或重置待执行队列。

## 可访问性与触控

- 左右切换按钮设置 `aria-controls` 和 `aria-expanded`。
- 抽屉打开时将焦点移入面板，关闭后还原到触发按钮。
- 抽屉遮罩可点击，`Esc` 可关闭。
- 所有图标按钮继续使用 Lucide 图标并保留可读 `title`。
- 触控目标维持至少 40 像素。
- 使用现有 `safe-area-inset-*` 和 `100dvh` 处理 iPad 状态栏、主屏幕模式和屏幕键盘。
- 长工作区路径、会话标题、模型名称和文件名使用省略或内部滚动，不能改变栏宽。

## 错误处理

- 会话读取失败：左栏显示错误和重试按钮，对话区保持可用。
- 额度或任务读取失败：右栏对应区域显示错误和重试按钮。
- 连接断开：保留当前布局与可见内容，禁用需要电脑响应的操作。
- 本地状态损坏：忽略无效值并恢复首次默认状态。
- 屏幕旋转期间已有请求继续完成，结果渲染到对应面板，不重复发送。

## 测试与验收

### 自动化逻辑测试

- 视口分类不会把低高度横屏手机识别为 iPad 三栏。
- 首次横屏状态为左开右收。
- 保存并恢复左右栏状态。
- 损坏的本地状态回退到默认值。
- 历史会话按 `cwd` 分组，当前会话信息保持完整。

### 视觉与交互 QA

- `320x700`：紧凑手机。
- `430x850`：普通手机。
- `768x1024`：iPad 竖屏，左右面板为覆盖抽屉。
- `1024x768`：iPad 横屏，首次左开右收，可展开右栏。
- `1366x1024`：iPad Pro 横屏，三栏同时展开。

每个 iPad 视口检查：消息与输入框无重叠、左右栏切换、遮罩关闭、旋转恢复、会话切换、模型选择、额度和任务区域、长文本约束，以及主屏幕安全区域。

### 回归验证

- 运行全部桌面 Node 测试。
- 运行 Electron QA 并生成手机与 iPad 截图。
- 检查截图像素非空、布局边界稳定、按钮和文本无重叠。
- 重新生成 Windows Setup 与 Portable 客户端，因为移动网页随电脑端客户端分发。

## 非目标

- 不开发原生 iPadOS 应用。
- 不改变配对码、连接令牌或 Tailscale 连接方式。
- 不增加新的后端工作区管理接口。
- 不重构桌面端主界面。
- 不改变现有模型供应商配置格式。
