# 计划审批可读布局与后台任务状态设计

## 目标

同一轮客户端更新解决两个已经直接影响使用的问题：

1. 桌面计划审批窗口套用了权限弹窗的两列网格，正文被挤进约 40px 左栏，三个动作按钮被拉成整窗色条，用户完全读不到计划。
2. 后台任务被模型或用户主动停止后，桌面把合成状态 `signal: "killed"` 当成 pytest 失败，并提示「请展开任务输出」，但对话里没有可展开的任务输出。

本轮不改主题系统、不改 ACP 协议、不自动批准计划、不禁止 `kill_task`。

## 问题一：计划审批窗口不可读

### 根因

`#plan-approval-dialog` 的表单同时使用 `.modal-body` 和 `.plan-approval-body`。`.modal-body` 是权限/信任弹窗的 `40px | 1fr` 网格，左列留给 `.modal-icon`。计划窗没有图标，于是：

- `.modal-copy` 落入 40px 列，标题、UUID、Markdown、意见框全部竖排。
- `.modal-actions` 被 `grid-column: 2` 甩到右列，并随左列高度拉伸。
- `.primary-command { width: 100% }` 让「批准并执行」吃掉整列。
- `.plan-approval-body` 只有 `max-height`，没有 `overflow` 和单列覆盖。

### 界面结构

计划审批使用独立单列布局，不再复用 `.modal-body` 网格。窗口分区固定为：

1. 标题行：eyebrow「计划审批」、主标题「确认下一步执行方案」、可读的工作区/会话名、稍后处理按钮。
2. 可滚动 Markdown 预览，占满剩余高度。
3. 紧凑修改意见框，聚焦或有内容时再升高。
4. 状态文案。
5. 底部固定三键：放弃计划、提出修改意见、批准并执行。

关闭窗口（`Esc`、稍后处理、点关闭）不得提交审批结果。待处理计划保留在输入区上方的胶囊条，点击「查看计划」重新打开同一窗口。

「提出修改意见」在意见为空时禁用。「放弃计划」需要一次 `confirm`。批准是主操作，三键固定高度，不得随正文被拉高。

工作区名优先显示路径末段；只有 session id 时显示缩短形式，完整值放在 `title`。

手机/iPad 使用同一套文案、同一套关闭/重开/确认规则。移动端已是单列，本轮补齐横幅、确认和空意见禁用。

## 问题二：后台任务「信号 killed」

### 根因

本地终端在主动 `kill_and_finalize` 且没有保留操作系统退出码时，写入合成 `signal: "killed"`。桌面 `backgroundTaskFailure()` 把任何非空 `signal` 都当成失败，拼出：

`后台任务“python -m pytest …”执行失败（信号 killed）。请展开任务输出查看原因。`

这不是 OS `SIGKILL`，也不是 pytest 断言失败。超时、输出上限、OOM 分别使用 `timeout` / `max_runtime` / `output_limit` / `oom`。真正的测试失败是退出码非 0。

渲染端 `handleUpdate` 忽略 `task_completed`，所以提示里的「展开任务输出」没有对应 UI。错误卡的「技术详情」只是重复那句中文。

### 规则

`backgroundTaskFailure()` 只对真实失败返回对象：

- 主动停止：`explicitly_killed` 或 `signal` 为 `killed` / `cancelled` → 返回 `null`，不发 `agent:turn-error`，不把任务条打成失败。
- 超时、超限、OOM、非 0 退出码 → 仍视为失败，但用中文原因，不再写「信号 xxx」。
- 失败消息附带截断后的 `output`，没有输出时提示去任务监控查看，不再假装对话里已经有折叠输出。

渲染端收到 `task_completed`（无论包在 `update` 里还是顶层）后，在当前助手活动流插入一行终端活动：

- 主动停止：状态「已停止」，详情说明这不是测试失败。
- 真实失败：状态「失败」，自动展开输出。
- 成功：状态「完成」，输出可展开。

不在本轮禁止模型调用 `kill_task`。长测试被误杀属于模型策略问题；客户端先停止误报，并让用户能看见真实输出。

## 范围

包含：

- 桌面/移动计划审批 HTML、CSS、交互。
- `ux-policy` 会话标签。
- `agent-events` 后台任务分类。
- 桌面/移动把 `task_completed` 画进活动流。
- 对应 Node 契约测试。

不包含：

- 改 Rust 杀进程语义。
- 自动批准计划。
- 全面重做新任务页或侧栏。
- 禁止后台 `pytest` 被停止。
