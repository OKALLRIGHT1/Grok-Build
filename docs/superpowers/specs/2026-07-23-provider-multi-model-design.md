# 供应商多模型设计

## 目标

将当前“一条 API 配置对应一个模型”的结构改为“一个供应商包含多个模型”。用户添加供应商后，只需重复填写模型名称和模型标识；API 地址、API Key 和默认接口协议由供应商统一管理。

## 数据结构

桌面客户端内部保存供应商数组。供应商字段为 `id`、`name`、`baseUrl`、`apiBackend` 和 `models`；API Key 继续单独加密保存，但索引由模型 ID 改为供应商 ID。

每个模型保存 `id`、`name`、`model`、可选的 `apiBackend` 覆盖值，以及上下文长度、最大输出、Temperature 和 Top P。模型没有设置 `apiBackend` 时继承供应商默认值。

供应商 ID 在创建时根据名称自动生成，创建后保持不变且不在界面中编辑。模型 ID 在所有供应商之间保持唯一，以便继续作为 CLI `config.toml` 中的 `[model."id"]` 标识。新建时根据供应商和模型标识自动生成；高级设置中允许修改，保存前检查冲突。

## 配置输出

CLI 仍然读取原有的 `[model.*]` TOML，不需要修改 CLI 协议。桌面客户端同步配置时将供应商展开为多个模型块：每个块写入供应商的 `base_url`、供应商密钥对应的同一 `env_key`，以及模型自己的参数。模型协议优先使用覆盖值，否则使用供应商默认协议。

环境变量按供应商 ID 生成，因此同一供应商下的所有模型共用一个解密后的 API Key。

## 兼容迁移

读取现有平铺 `custom-models.json` 时，将每条旧模型配置迁移为一个供应商及其单个模型。旧密钥从模型 ID 迁移到新供应商 ID，并立即使用新结构原子写回。迁移不得删除无法解密的密钥，也不得覆盖用户在非托管 TOML 区块中的配置。

若多条旧配置的 API 地址、接口协议和加密密钥完全一致，可归并到同一个供应商；否则保持为独立供应商，避免错误共享凭据。迁移后生成的模型 ID 保持不变，因此现有会话和模型选择不会失效。

## 界面

“模型与 API”弹窗首先展示供应商分组。每个供应商显示名称、API 域名、默认协议、密钥状态和模型数量，并提供编辑供应商、添加模型和删除供应商操作。供应商下展开模型列表，每个模型可编辑或删除。

新建供应商的基础表单仅显示供应商名称、API 地址、API Key 和默认接口协议。新建模型的基础表单仅显示显示名称和模型标识。

配置 ID、协议覆盖、上下文长度、最大输出、Temperature 和 Top P 放入折叠的“高级设置”。配置 ID 自动生成；模型协议默认显示“继承供应商设置”。

删除供应商时，如果其下仍有模型，界面明确显示将删除的模型数量并要求确认。删除最后一个模型不会自动删除供应商，便于稍后重新添加模型。

## 错误处理

保存前验证供应商 ID、模型 ID、URL、协议和数值范围。模型 ID 冲突、托管区块外存在同名 TOML 模型、迁移数据损坏或文件写入失败时，保留原文件并向界面返回可读错误。

API Key 留空表示保留现有密钥；显式选择“清除密钥”才会删除。编辑供应商显示名称不会改变供应商 ID、密钥环境变量或其下模型 ID。

## 测试

自动化测试覆盖：一个供应商保存多个模型、共享密钥环境变量、模型协议继承与覆盖、TOML 展开、旧平铺数据迁移、相同供应商归并、模型 ID 冲突、删除单个模型、删除供应商以及保留非托管 TOML。

Electron 界面验证覆盖：供应商分组展示、基础/高级表单、添加第二个模型、编辑和删除操作、错误提示，以及窗口窄宽度下字段和按钮不重叠。
